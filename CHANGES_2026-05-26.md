## Completed — Hetha_app (Flutter)

### Tier A — Bug fixes

#### A1. `address_service.dart:deleteAddress` firstWhere crash fixed

- `firstWhere` without `orElse` threw `StateError` when the address wasn't
  in the local list (stale cache scenario).
- Fixed by using `.cast<Address?>().firstWhere(..., orElse: () => null)` and
  guarding the `isDefault` check with a null check.

#### A2. `address_service.dart:updateAddress` default-management race fixed

- Previously: `_clearOtherDefaults(userId)` ran before the update when
  `address.isDefault` was true, leaving a brief window with zero defaults.
- Now: calls `update_address_as_default` RPC which atomically clears other
  defaults and updates the target address in a single transaction.
- Includes a fallback path if the RPC hasn't been deployed yet (logs a
  warning and uses the old non-atomic approach).

#### A3. `subscription_scheduler.dart` deleted

- Was already commented out in `main.dart`. File removed entirely to prevent
  future confusion. Scheduler logic belongs in pg_cron / Edge Function (D4
  decision still pending).

### Tier B — UX & maintainability

#### B6. `pause_service.dart` non-atomic loops fixed

- `pauseDates` and `resumeDates` previously made multiple sequential DB calls
  (select → delete → insert per range/date). Network failure mid-loop left
  half-applied state.
- Now: calls `upsert_pauses` / `remove_paused_dates` RPCs that handle all
  merge/split logic in a single Postgres transaction.
- Includes non-atomic fallback if RPCs haven't been deployed yet.
- Migration: `2026_05_26_atomic_pause_rpcs.sql` creates both functions.

### Tier C — Cleanup / hygiene

#### C1. `analysis_options.yaml` corruption fixed

- First line had garbage text `Remuneration: Half - TAship as per Insititute Norms`.
  Removed — file now starts with the standard comment header.

#### C2. Dead code deleted

- `order_service.dart:createTestOrder` — threw `UnimplementedError`, no callers.
- `cart_service.dart:fetchCart` — superseded by `fetchCartWithDetails`. The
  `CartNotifier.fetchCart()` method in `cart_provider.dart` already calls
  `fetchCartWithDetails`, not this method.

#### C3. Dead `response == null` checks removed

- `product_service.dart` — removed 3 dead null checks after `.select()` calls
  (in `getProducts`, `getProductById`, `getBestSellerProducts`). Supabase
  returns an empty list or throws, never null.
- Also removed a commented-out `print` statement.
- `user_service.dart` null check left intact — it uses `.maybeSingle()` which
  legitimately returns null.

#### C (withOpacity). Migrated all `withOpacity` → `.withValues(alpha:)`

- Deprecated in Flutter 3.32. 13 usages across 5 files migrated:
  - `walletpage.dart` — 7 usages (lightBrown, white, black, orange, purple,
    primaryBrown, color)
  - `select_address_page.dart` — 2 usages (Color(0xFFA08476))
  - `cart_page.dart` — 2 usages (grey, black)
  - `home_skeleton.dart` — 1 usage (white)
  - `product_details_page.dart` — 1 usage (brown)
- Zero `withOpacity` calls remain in the codebase.

#### C5. Dependencies updated

- `flutter pub upgrade` bumped 72 packages within existing constraints.
- Manually bumped: `intl` ^0.18→^0.20.2, `flutter_lints` ^5→^6,
  `build_runner` ^2.4.7→^2.4.13.
- Skipped Riverpod 2→3 (major breaking changes across many files) and
  share_plus 7→12+ (API changed from `Share.share` to `SharePlus`).
- Remaining 38 packages with newer incompatible versions are mostly Riverpod
  ecosystem + share_plus + build system packages that need coordinated
  migration.

### Tier D — Design fixes

#### D1. Razorpay edge function wallet atomicity fixed

- `supabase/functions/razorpay/index.ts` had a classic read→compute→write
  race: two concurrent successful payments could both read the same balance,
  losing one credit.
- Replaced with a single `update_wallet_balance` RPC call that handles the
  row lock, balance update, and transaction insert atomically.

#### Reviews UI UUID fix (was Decision #25)

- `order_page.dart` was passing wrong IDs to `ReviewPage`:
  - `productId` received `variant_id` (from `order_items`) instead of the
    actual `product_id` (UUID from `products` table).
  - `orderId` received `order_number` (like `HET-1234`) instead of the
    order's UUID.
- Fix: updated the order query to join `product_variants(product_id)`,
  updated `_mapOrderData` to extract `product_id` from the join, and
  changed `order_page.dart` to pass `order['id']` (UUID) for `orderId`.

## Completed — Hetha_admin

### Security headers added to `next.config.ts`

- Was completely empty (no config). Now includes:
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY`
  - `X-XSS-Protection: 1; mode=block`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`
- Applied to all routes via `source: "/(.*)"`.

### `assignRole` misleading variable naming fixed

- `accessControlService.ts:assignRole` had `const authUserId = userId` where
  `userId` is the **target** user being assigned a role, not the acting admin.
- Renamed to `targetUserId` throughout the function. Comment updated from
  "Check if current user is a super admin" to "Check if target user is
  currently a super admin".

### Last 3 production `console.log` calls removed

- `app/page.tsx` — `console.log(error)` in login catch block (error already
  shown via toast).
- `services/customerService.ts` — `console.log("insert error", ...)` before
  throwing (redundant with the thrown error).
- `services/subscriptionService.ts` — `console.log('Subscription Service Loaded - V3')` module-level debug line.

### Server-side route/area mismatch check added

- `createAdHocSubscription` in `subscriptionService.ts` now validates that
  the provided `route_id` belongs to the same delivery area as the address's
  pincode before patching it onto the subscription.
- Fetches the route's `area_id`, then checks `delivery_area_pincodes` for a
  matching row. Throws `'Route does not serve the address pincode area'` on
  mismatch.
- The client-side `CreateSubModal` already filters routes by area (B1 from
  25 May), but this server-side check prevents direct API misuse.

### Subscription search `.or()` on embedded relations fixed

- `getSubscriptions` and `getNewSubscriptions` included
  `subscription_items.product_name_snapshot.ilike.%X%` inside `.or()`.
- PostgREST does **not** support embedded relation columns in `.or()` — the
  filter was silently ignored, giving the false impression product name
  search worked.
- Removed the unsupported filter. Search now covers `snapshot_name` and
  `snapshot_phone` only. Added explanatory comment noting a DB view/RPC
  would be needed for product name search.

### Admin dashboard summary cards built

- `app/admin/page.tsx` previously returned `<></>` (blank page).
- Now shows 4 summary cards in a responsive grid (1/2/4 columns):
  - **Today's Orders** — count of orders placed today
  - **Active Subscriptions** — total active subscription count
  - **Today's Wallet Credits** — ₹ sum of credit transactions today
  - **Total Customers** — count of non-adhoc users
- Client-side fetching with `Promise.all` for parallel queries.
- Skeleton loading state while data loads.

### `any` types cleaned up (services + API routes)

- **Services layer:** 48 `any` → 0. All 8 service files now fully typed.
- **API routes:** 49 `any` → 0. All 21 route files now fully typed.
- Total reduced from 239 → 142 (41% reduction).
- Remaining 142 are in page components (`.tsx` UI files), with `ad-hoc/page.tsx`
  (48) and `daily-ops/page.tsx` (15) being the biggest. These are tied to the
  large file refactoring task.

## Database migrations created

### `2026_05_26_update_address_as_default.sql` ✅ Applied

- Creates `public.update_address_as_default(p_user_id, p_address_id, p_address_data)` RPC.
- Atomically: clears all `is_default` for the user, then updates the target
  address with provided data and sets `is_default = true`.

### `2026_05_26_atomic_pause_rpcs.sql` ✅ Applied

- Creates `public.upsert_pauses(p_subscription_id, p_ranges)` — merges new
  pause ranges into existing ones, handling overlap and adjacency in one
  transaction.
- Creates `public.remove_paused_dates(p_subscription_id, p_dates)` — removes
  specific dates from pause ranges, splitting ranges as needed.

### `2026_05_26_pg_cron_cancel_expired_subs.sql` ✅ Applied

- Enables `pg_cron` extension.
- Schedules daily job `cancel-expired-subscriptions` at 18:30 UTC (midnight IST).
- Auto-cancels subscriptions where `status = 'active'` and `end_date < CURRENT_DATE`,
  setting `cancellation_type = 'expired'`.

### D3. addressType casing migration ✅ Applied

- `UPDATE addresses SET address_type = lower(address_type) WHERE address_type ~ '[A-Z]'`
- Returned 0 rows (all already lowercase from app-side B9 fix).
