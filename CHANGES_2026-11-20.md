## 1. Database (migration 044)

`internal.wallet_forecast` (039) always started tomorrow. If a day's run is finalized during that day, today's charge was missing, and "covers until" came out one delivery day too late.

Today is now counted by what is still owed:

| Today's state | Counted |
|---|---|
| run not generated yet | expected amount |
| generated, not paid | unpaid amount |
| paid | 0 |
| skipped or cancelled | 0 |

This is correct whether runs are finalized the evening before (today is already paid, so nothing changes) or during the day.

The new field `covers_beyond_horizon` is true when every delivery in the window is covered.

**Kept as it was:** orders on settlement hold count 0. Under D-9 they are never charged automatically, so they aren't money the wallet has to cover.

Tests (13b/13c):
- The 039 cases still pass, now with subscriptions starting tomorrow.
- New cases: today not generated, today generated and unpaid, today paid, an order on hold, a wallet lasting past the window, a wallet running out inside it, and no subscriptions.

## 2. Admin panel

Customer profile cards (`ProfileTab.tsx`):
- **"Daily commitment" → "One delivery of each".** The hint explains it is not a daily amount. The value now comes from the database (`per_delivery_total`). The panel's own sum is only a fallback.
- **"Wallet covers until"** shows "Over 30 days" when the wallet lasts past the window, or the day it runs short.
- **"Kept for next delivery" → "Kept in the wallet"**, with a hint that the customer can't spend it on orders.

`lib/types.ts` gets `covers_beyond_horizon`.

## 3. Customer app

Wallet page:
- Shows "Covers your deliveries for more than 30 days" when that's true.
- The reserve sentence now reads "₹X stays in your wallet for the next delivery of each subscription and cannot be used for shop orders."
- New line under the balance, "Available for shopping: ₹Y", showing the forecast's `available` (balance minus reserve, worked out by the database). It only shows when the customer has live subscriptions.

## 4. Docs

`docs/DATA_MODEL.md` describes the forecast window and the new field. `docs/IMPLEMENTATION_PLAN.md` W-02 notes the change to the "today is never included" rule.
