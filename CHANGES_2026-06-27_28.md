# CHANGES — 2026-06-27 & 2026-06-28

## Summary

Two major work sessions covering the **Daily Operations production system** (admin panel), **order tracking management**, **delivery partners**, and **wallet page improvements** (customer app).

---

## 2026-06-27 (Saturday)

### Admin Panel (Hetha_admin)

#### 1. Daily Operations — Full Production System
The core feature of this session. Replaces the client's manual Excel-based workflow.

**Database migrations created & deployed:**
- `001_daily_ops_runs.sql` — New `daily_ops_runs` table tracking per-date state (draft → finalized → reconciled) with RLS policies
- `002_finalize_daily_run.sql` — PostgreSQL RPC that atomically locks all pending orders and deducts wallets using the existing `update_wallet_balance` function, with per-order error handling

**Backend (API routes + service layer):**
- Rewrote `/api/admin/daily-ops/route.ts` with new POST actions: `finalize`, `reconcile`, `unlock`
- Added lock enforcement on all PATCH operations — rejects edits on finalized dates
- Added `bulk-update-status` action for marking multiple orders at once
- Added `run-status` GET action to check if a date is draft/finalized/reconciled
- Created `/api/admin/daily-ops/sheets/route.ts` — generates per-route printable HTML delivery sheets with page breaks, load summary, checkboxes, signature columns
- Created `/api/admin/daily-ops/export/route.ts` — CSV download with all order data
- Added 8 new service functions: `getRunStatus`, `finalizeRun`, `unlockRun`, `reconcileRun`, `bulkUpdateStatus`, `isDateLocked`, `getOrdersForSheets`, `getExportData`

**Frontend (daily-ops page complete rewrite — 1001 lines):**
- Status badge showing DRAFT / FINALIZED / RECONCILED
- Action toolbar: Generate, Finalize (with confirmation modal showing wallet deduction warning), Reconcile, Unlock (super_admin), Print Route Sheets, Export CSV, Refresh
- Bulk selection with checkboxes + "Mark Delivered" / "Mark Skipped" bulk actions
- 3 tabs: Run Sheet (orders table with expand/edit), Live Status (aggregated procurement view), Reconciliation (compact delivery confirmation table)
- Payment failure badges (red) for orders where wallet deduction failed
- Lock enforcement in UI — editing disabled when date is finalized
- Added `daily_ops:finalize` permission key to constants

#### 2. Subscription Cancellation
- Added cancel button (✕) on active/pending_cancellation subscriptions in the admin subscriptions page
- Shows confirmation dialog with customer name
- On cancel: sets status to `cancelled`, end_date to today
- Auto-deletes unfinalized future `subscription_daily_orders` for that subscription (prevents stale deliveries)

#### 3. Performance & Bug Fixes (earlier in the day)
- Improved page load performance with `loading.tsx` and `React.cache`
- Fixed double spinner on products page
- Added full order details in expanded row (customer info, address, payment)
- Fixed invisible text caused by dark mode CSS bleeding into components
- Fixed status dropdown text color

### Customer App (Hetha_app)

#### 4. Razorpay Edge Function Fix
- Fixed the edge function to mark `payment_status` as `'paid'` after successful verification

## 2026-06-28 (Sunday)

### Admin Panel (Hetha_admin)

#### 5. Order Tracking Management
- Updated orders query to include `order_tracking` data
- Added `TrackingSection` component in the expanded order panel
- Admin can now add/edit tracking info: courier, AWB number, tracking URL, customer message
- Updated `/api/admin/orders/[id]/route.ts` to support tracking upsert (inserts if new, updates if existing)

#### 6. Delivery Partners Page (new)
- Created new admin page at `/admin/delivery-partners`
- Full CRUD: add, edit, toggle active/inactive, delete courier partners
- Each partner has a `tracking_url_template` with `{tracking_id}` placeholder
- Created `/api/admin/delivery-partners/route.ts` (GET/POST/PATCH/DELETE)
- Updated `TrackingSection` in orders page: courier is now a **dropdown** populated from delivery partners table
- When admin selects a partner and types AWB number, the tracking URL auto-fills from the template
- Added "Delivery Partners" to the sidebar navigation
- **Database:** Created `delivery_partners` table with 4 seeded partners (DTDC, Delhivery, BlueDart, Trackon)

#### 7. Database Fixes (deployed during testing)
- Fixed `finalized_by` column type mismatch (was casting uuid to text)
- Added `'failed'` to `subscription_daily_orders.payment_status` CHECK constraint
- Fixed `update_wallet_balance` function ambiguity — dropped old 5-param overload after adding 7-param version with `reference_type`/`reference_id` support
- Fixed `p_reference_id::uuid` cast in the wallet balance function
- Updated `finalize_daily_run` RPC to pass `reference_type='subscription'` and `reference_id=daily_order_id` when deducting wallets

### Customer App (Hetha_app)

#### 8. Order Tracking (Dynamic URLs)
- Updated `OrderTrackingService.generateTrackingUrl()` to prioritize `tracking_url` from the database (set by admin)
- Removed hardcoded courier URL patterns as primary — they're now fallback only
- Simplified `OrderTrackingDetails` widget — single "Track Order" button instead of method dropdown
- **Track Order button is now hidden** when no tracking URL/AWB/LR number exists (was redirecting to useless Google search)
- Added `_TrackingInfoCard` showing courier name, tracking ID, and customer message on the order details page
- Removed "Need Help with this Order?" button (not functional)

#### 9. Wallet Page — UX Improvements
- **No more full-page spinner after recharge** — only shows on initial page load
- **"Verifying payment..." indicator** — small spinner + text appears below balance during the 2-3 second verification window
- **Smooth counter animation** — balance counts up from old to new value (800ms ease-out curve)
- **"Days left" animation** — also animates counting up

#### 10. Wallet Page — Transaction Details Fix
- Subscription order cards now show the actual description ("Subscription delivery 2026-06-28") instead of generic "Daily delivery"
- **Items are now fetched and displayed** for both subscription and regular order transactions:
  - Subscription: fetches from `subscription_daily_order_items` using `reference_id` (daily order UUID)
  - Regular orders: fetches from `order_items` by looking up the order UUID via order number extracted from description
- Order number (e.g., "ORD-20260627140900") shown in subtitle instead of blank "Order"
- Handles multi-subscription users correctly by matching daily order via `reference_id`
