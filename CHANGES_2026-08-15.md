# Changes — 2026-08-15

## Feature: Product Delivery Scope (`delivery_scope`)

Products can now be tagged as **Local Delivery** or **All India**, controlling
which customers see them based on the delivery address's pincode serviceability.

### Motivation

The client needed to restrict certain products (fresh dairy, local items) to
serviceable pincodes without manually assigning pincodes to every product. The
solution reuses the existing `delivery_areas` → `pincodes` infrastructure: if a
product is `local`, it's available only where Hetha delivers directly. If
`all_india`, it's available everywhere.

---

## Database — Migration 016 (`docs/db/migrations/016_delivery_scope.sql`)

### Schema change

```sql
ALTER TABLE public.products
  ADD COLUMN delivery_scope text NOT NULL DEFAULT 'local'
    CHECK (delivery_scope IN ('local', 'all_india'));
```

- Backfilled from existing `is_local` boolean: `is_local = true` → `'local'`,
  `is_local = false` → `'all_india'`.
- `is_local` is retained for backward compat but is now **deprecated** — the
  admin panel writes both columns in sync.
- New index: `idx_products_delivery_scope`.

### New helper function

```sql
CREATE OR REPLACE FUNCTION internal.serviceable_area_id(p_pincode text)
RETURNS uuid ...
```

Returns the `area_id` if the pincode is in an active delivery area, `NULL`
otherwise. Single point of truth for "is this pincode serviceable?"

### Enforcement in `internal.place_order_core`

After the address lookup, before pricing:

```sql
IF internal.serviceable_area_id(v_address.pincode) IS NULL
   AND NOT COALESCE(p_is_admin, false)
   AND EXISTS (
     SELECT 1 FROM normalize_cart(p_cart_items) c
     JOIN product_variants pv ON pv.id = c.variant_id
     JOIN products pr ON pr.id = pv.product_id
     WHERE pr.delivery_scope = 'local'
   )
THEN
  RAISE EXCEPTION 'Some items in your cart are only available for local delivery...';
END IF;
```

- Admin callers (`p_is_admin = true`) bypass this — same pattern as the 3-day
  buffer bypass.
- `all_india` products pass through regardless of pincode.

## Customer App (Hetha_app)

### `lib/services/product_service.dart`

- `getProducts()` now accepts an optional `bool? isServiceable` parameter.
- `getBestSellerProducts()` now accepts an optional `bool? isServiceable` parameter.
- When `isServiceable == false`, queries add `.eq('delivery_scope', 'all_india')`
  — only nationwide products are returned.
- When `isServiceable` is `true` or `null`, all products are returned (a
  serviceable pincode can order everything).

### How callers determine serviceability

The existing `DeliveryAreaService.getDeliveryAreaFromPincode(pincode)` returns
`null` when the pincode isn't in any active delivery area. Callers pass
`isServiceable: area != null` to `ProductService`.

## How it works end-to-end

1. **Admin** sets "Local Delivery" or "All India" on a product → `delivery_scope` column.
2. **Flutter app** resolves the user's address pincode via `DeliveryAreaService`:
   - Pincode in a delivery area → serviceable → show full catalogue.
   - Pincode not found → not serviceable → show only `all_india` products.
3. **Server enforcement** in `place_order_core`: even if a local product reaches
   checkout (deep link, stale cache, etc.), the order is rejected with a clear
   error message.
4. **No per-product pincode management needed**: the master pincode list at
   `/admin/delivery-areas` automatically applies to all `local` products.
   Adding/removing a pincode there changes product availability with zero product
   edits.

## Feature: Admin-Managed Homepage Banners (Migration 017)

Replaces hardcoded carousel images with a Supabase-backed banner system.

### Database

```sql
CREATE TABLE public.banners (
  id uuid PK, image_url text NOT NULL, link_url text,
  display_order integer NOT NULL, is_active boolean NOT NULL, created_at timestamptz
);
```

RLS: public read for active banners, admin write via `banners:edit`.
Storage bucket: `banners` (public).

### Admin Panel

- New page: `/admin/banners` — upload, reorder, toggle active/hidden, delete
- API route: `app/api/admin/banners/route.ts` (GET/POST/PUT/DELETE)
- Sidebar: Banners link under Engagement, gated by `banners:edit`
- `lib/constants.ts`: added `banners:edit` permission

### Customer App

- Home page carousel now fetches from `banners` table (active, ordered)
- Uses `CachedNetworkImage` for efficient loading
- Supports optional `link_url` (external or internal navigation on tap)
- Cached per session
