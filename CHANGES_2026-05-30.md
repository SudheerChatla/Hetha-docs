## 1. Subscription Calendar Independence from Default Address

**Problem:** The subscription calendar on the home page and subscription page was reading `users.pincode` (stale) which could be affected by home page address changes.

**Fix:**
- `subscription_page.dart` — `_loadUserAreaAndPincode()` now reads pincode from the subscription's own `snapshot_pincode` first, falls back to `users` table only for users without active subscription.
- `home_page.dart` — Calendar Consumer now uses `userActiveSubscriptionsProvider` instead of `activeAddressProvider` for pincode.

**Files changed:**
- `lib/screens/subscription/subscription_page.dart`
- `lib/screens/home/home_page.dart`

## 2. Checkout Page — Selecting Address No Longer Changes Default

**Problem:** When user picked a different address during checkout, it called `setAddressAsDefault()` which changed the global default address.

**Fix:**
- `checkout.dart` — Added local `_checkoutAddress` state. Initializes from default on load. Selecting a different address only updates local state, no DB call.
- `select_address_page.dart` — When `fromCheckout: true`, `_handleAddressSelection()` skips DB persistence (only updates local UI).

**Files changed:**
- `lib/screens/checkout/checkout.dart`
- `lib/screens/address/select_address_page.dart`

## SQL to Run in Supabase (already executed)

```sql
ALTER TABLE public.subscriptions ADD COLUMN IF NOT EXISTS label TEXT;

-- create_subscription RPC replaced (see doc-schema/subscription_rpc.sql for full source)

CREATE OR REPLACE FUNCTION get_user_daily_commitment(p_user_id UUID)
RETURNS NUMERIC AS $$
  SELECT COALESCE(SUM(si.unit_price * si.quantity), 0)
  FROM public.subscription_items si
  JOIN public.subscriptions s ON s.id = si.subscription_id
  WHERE s.user_id = p_user_id
    AND s.status IN ('active', 'pending_cancellation')
    AND si.is_active = true;
$$ LANGUAGE sql;
```
