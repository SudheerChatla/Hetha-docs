# CHANGES — 2026-06-29

## Customer App (Hetha_app)

### Wallet Page — Accurate "Days Left" Simulation

**Problem:** The wallet page showed "₹17500/day · 5 days left" by dividing wallet balance by the total subscription cost — but this was wrong for users with mixed delivery frequencies (daily + alternate day). It treated every subscription as if it delivers daily, overstating the daily cost and understating days left.

**Solution:** Replaced the simple division with a **day-by-day forward simulation**:

1. Fetches all active subscriptions with their `delivary_frequency`, `start_date`, and item costs
2. For each day (up to 90 days forward), checks which subscriptions actually deliver based on:
   - `frequency == 1` → delivers every day
   - `frequency > 1` → delivers only when `(daysSince(start_date) % frequency) == 0`
3. Sums the cost for that day, subtracts from balance
4. Stops when balance can't cover a day's deliveries
5. Calculates 7-day average for the "₹X/day avg" display

**Display changed from:**
```
₹17500/day · 5 days left
```

**To:**
```
₹10714/day avg · 11 days left
```

**Notes:**
- Does NOT account for pauses (conservative — shows fewer days than actual, which is fine)
- Does NOT change the 3-day buffer rule for subscription creation (that still uses the old conservative RPC)
- No new API/RPC needed — calculated client-side from subscription data already fetched
- Simulation runs in microseconds (max 5 subs × 90 days = 450 iterations)

**File modified:** `lib/screens/wallet/walletpage.dart`
