# CHANGES — 2026-07-02

## Customer App (Hetha_app)

### 1. Push-Triggered Auto-Refresh (Zero Realtime Connections)

Upgraded the notification system so push notifications automatically refresh screen data — eliminating the need for realtime WebSocket connections for most features.

**How it works:**
- Push notification arrives → `NotificationService` emits a `NotificationEvent`
- Active screens listen to the event stream and refresh their data
- Result: instant updates with 0 extra connections (unlimited users supported)

**Screens that auto-refresh on push:**

| Screen | Trigger | What refreshes |
|--------|---------|----------------|
| Subscription calendar | "Order Delivered" push | Daily modifications reload → blue dot appears |
| Home page badge | Any push | Unread count updates instantly |
| Wallet | Already had realtime `.stream()` | Kept as-is (1 connection) |

**Notification tap navigation:**
- Wallet notification → opens Wallet page
- Delivery notification → opens Home page
- Order notification → opens Orders page

**Files changed:**
- `lib/services/notification_service.dart` — added `NotificationEvent` enum, event stream, badge stream, navigator key for tap navigation
- `lib/main.dart` — added global navigator key, passed to notification service
- `lib/screens/subscription/subscription_page.dart` — listens to `orderDelivered` events, auto-refreshes calendar
- `lib/screens/home/home_page.dart` — listens to badge count stream, updates bell icon live

### 2. Query Performance Optimizations

Added limits to unbounded queries and new composite database indexes for production scale.

**Query limits added:**
- `getUserOrders()` — `.limit(50)` (was unbounded, would slow down with 500+ orders per user)
- `getUserSubscriptions()` — `.limit(20)` (was unbounded)

**New database indexes** (run in Supabase SQL Editor):
- `idx_sdo_date_status_finalized` on `subscription_daily_orders(delivery_date, status, is_finalized)` — speeds up daily-ops generate/finalize/reconcile
- `idx_wallet_tx_user_created` on `wallet_transactions(user_id, created_at DESC)` — speeds up wallet history
- `idx_orders_user_placed` on `orders(user_id, placed_at DESC)` — speeds up customer order history
- `idx_pauses_subscription_id` on `subscription_pauses(subscription_id)` — speeds up pause lookups
- `idx_device_tokens_user_id` on `device_tokens(user_id)` — speeds up notification sending

## Admin Panel (Hetha_admin)

### 3. Realtime on Daily Ops Page (Live Delivery Status)

The Daily Ops page now shows **live order status updates** without manual refresh.

**What happens:**
- Admin generates run sheet → orders appear
- Rider/admin marks order as delivered → status changes **instantly** on screen
- New orders generated → automatically appear in the list
- Progress counter (pending/delivered) updates in real time

**Technical:**
- Supabase Realtime channel subscribed to `subscription_daily_orders` filtered by current date
- `UPDATE` events → in-place status update (no full refetch)
- `INSERT` events → triggers full refetch to get joined data
- Auto-cleanup on date change or page unmount
- Cost: 1 WebSocket connection per admin tab

---

### 4. Realtime on Orders Page (New Order Alerts + NEW Badge)

The Orders page now shows **new orders instantly** with visual distinction.

**Features:**
- New order placed by customer → toast "📦 New order received!" + order appears in list
- **"NEW" badge** (green, pulsing) shown on:
  - Orders that arrived via realtime while the page was open
  - Any order placed within the last 30 minutes (timestamp-based)
- Badge auto-disappears after 30 minutes
- TanStack Query invalidated on new order → list re-fetches with the new order included

**Technical:**
- Supabase Realtime channel subscribed to `INSERT` on `orders` table
- `newOrderIds` state tracks which orders are "new" (for badge)
- Auto-cleanup on unmount

---

### 5. Reusable Realtime Hook

Created `hooks/useRealtimeSubscription.ts` — a generic hook for adding realtime to any admin page:
- `useRealtimeSubscription(channelName, subscriptions[], enabled)` — multi-table, single connection
- `useRealtimeInserts(table, onInsert)` — convenience for new row alerts
- `useRealtimeUpdates(table, onUpdate)` — convenience for status changes
- Auto-cleanup on unmount, single WebSocket per channel

## Supabase Configuration

### 7. Enabled Realtime for Tables

Added tables to the `supabase_realtime` publication so Realtime Postgres Changes can broadcast updates:

```sql
alter publication supabase_realtime add table orders;
alter publication supabase_realtime add table subscription_daily_orders;
alter publication supabase_realtime add table users;
```

| Table | Used by |
|-------|---------|
| `orders` | Admin Orders page — new order alerts |
| `subscription_daily_orders` | Admin Daily Ops — live status updates |
| `users` | Flutter app — wallet balance stream |
