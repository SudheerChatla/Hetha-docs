#### Code changes

into `package:flutter_riverpod/legacy.dart`.** Every file declaring these now
imports `legacy.dart` in addition to (or instead of) the main flutter_riverpod
import:

| File | Symbols used | Import change |
|---|---|---|
| `lib/providers/address_provider.dart` | `StateNotifier`, `StateNotifierProvider` | + `legacy.dart` |
| `lib/providers/cart_provider.dart` | `StateNotifier`, `StateNotifierProvider` | + `legacy.dart` |
| `lib/providers/pause_provider.dart` | `StateNotifier`, `StateNotifierProvider` | + `legacy.dart` |
| `lib/providers/subscription_address_provider.dart` | `StateNotifier`, `StateNotifierProvider` | + `legacy.dart` |

**Riverpod 3 removes `AsyncValue.valueOrNull`. `AsyncValue.value` now
returns `null` during error/loading states (was previously throw-on-error).**
Replaced 7 call sites:

| File | Line | Before | After |
|---|---|---|---|
| `lib/providers/address_provider.dart` | 166 | `.valueOrNull` | `.value` |
| `lib/screens/checkout/checkout.dart` | 65 | `.valueOrNull` | `.value` |

| `lib/screens/home/home_page.dart` | 951 | `.valueOrNull` | `.value` |

**`userAddressesStreamProvider` refactored.** The old implementation reached
into `notifier.state` and `notifier.stream` from outside the StateNotifier
class. Riverpod 3 properly enforces the `@protected`/`@visibleForTesting`
markers on those members (5 analyzer warnings post-bump). Replaced with the
idiomatic Riverpod-3 pattern — watch the underlying provider and convert the
`AsyncValue<List<Address>>` back to a `Stream<List<Address>>`:

```dart
final userAddressesStreamProvider =
    StreamProvider.family<List<Address>, String>((ref, userId) {
  final asyncAddresses = ref.watch(userAddressesProvider(userId));
  return asyncAddresses.when(
    data: (addresses) => Stream.value(addresses),
    loading: () => const Stream.empty(),
    error: (err, stack) => Stream.error(err, stack),
  );
});
```

The `StreamConcat` extension (manual rxdart-style stream concat) was only
used by the old shim — now dead code, deleted.

**Unused-import cleanup surfaced by the migration.** Two imports that were
masked by cascading compile errors before the migration are now removed:

- `lib/providers/navigation_provider.dart` — dropped
  `import 'package:flutter_riverpod/flutter_riverpod.dart';` (only `legacy.dart`
  needed for `StateProvider`).
- `lib/providers/subscription_address_provider.dart` — dropped
  `import 'package:supabase_flutter/supabase_flutter.dart';` (was always
  unused; analyzer didn't flag it before because compile errors suppressed
  lints).

#### What didn't need changing

- All `Provider`, `FutureProvider`, `StreamProvider`, `Provider.family`, and
  `FutureProvider.autoDispose` declarations work unchanged on 3.x.
- All `ConsumerWidget` / `ConsumerStatefulWidget` / `ref.watch` /
  `ref.read` / `ref.invalidate` call sites work unchanged.
- No `Ref` subclass (`FutureProviderRef`, `StateProviderRef`, etc.) was used
  in the codebase — Riverpod 3 removes them, but we had nothing to migrate.
- No `ProviderObserver` was registered, so the `ProviderObserverContext`
  parameter change has no impact.
- No `@riverpod` codegen, so all codegen-related breaking changes
  (mutations, `Notifier` lifecycle) are inapplicable.
