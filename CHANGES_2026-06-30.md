## Bug Fixes

### 7. Calendar tap behavior for delivered/today orders

**Problem:** Tapping a delivered date (blue dot) showed "Delivery scheduled" dialog instead of delivery details. Tapping today opened a non-modifiable edit screen.

**Fix:**
- Delivered orders (any date) → show read-only details dialog with "Delivery completed"
- Today → show read-only details dialog (can't modify today's order)
- Admin-finalized future orders → open edit view in read-only mode
- Added `RefreshIndicator` (pull-to-refresh) so users can see status updates without re-login

### 8. Subscription not showing after creation

**Problem:** After creating a subscription, the page still showed "No Active Subscription" until re-login.

**Fix:** Post-creation now does a full reload sequence: area info → subscription data → daily modifications.

## Push Notifications (New Feature)

### 9. Firebase Cloud Messaging Integration

Full push notification pipeline implemented:

**Flutter App (`Hetha_app`):**
- Added `firebase_core`, `firebase_messaging`, `flutter_local_notifications`
- `NotificationService` handles: permission request, FCM token registration/refresh, foreground display, background handling, notification tap
- Token stored in `device_tokens` table on app start
- Token removed on sign-out
- Android: `google-services.json`, `POST_NOTIFICATIONS` permission, FCM channel metadata, core library desugaring enabled

**Supabase:**
- New `device_tokens` table (user_id, fcm_token, platform, unique per user+token) with RLS
- Altered existing `notifications` table — added `read_at` (timestamptz) and `data` (jsonb) columns for in-app inbox support
- New indexes: `idx_notifications_user_created` (newest first), `idx_notifications_user_unread` (where read_at is null)
- `send-notification` Edge Function: accepts user_id + title + body, looks up tokens, calls FCM V1 API, auto-cleans stale tokens
- `FIREBASE_SERVICE_ACCOUNT_KEY` secret stored for Edge Function auth

**Admin Panel (`Hetha_admin`):**
- `services/notificationService.ts` — helper with `notifyOrderDelivered`, `notifyWalletDebited`, `notifyLowBalance`, `notifyCustom`
- Every notification is **saved to the `notifications` table** (in-app inbox) alongside the push delivery
- Automatic triggers:
  - **Finalize (daily-ops)** → "Wallet Debited — ₹X debited for today's delivery"
  - **Low balance (after finalize)** → "Low Wallet Balance ⚠️" (if balance < 3 days of daily cost)
  - **Mark delivered / Reconcile (subscription orders)** → "Order Delivered! 🥛"
  - **Mark delivered (normal one-time orders)** → "Order Delivered! 🥛"
  - **Ad-hoc subscription created** → "Subscription Started! 🎉"
- New admin page at `/admin/notifications` (added to sidebar):
  - Device token stats (total, Android, iOS)
  - Send custom notifications to all users or a specific user
  - Title + message input with preview
- `notifications:send` permission added to `PAGE_PERMISSIONS`

### 10. In-App Notification Inbox

**Flutter App (`Hetha_app`):**
- New `screens/notifications/notifications_page.dart`:
  - Paginated list (20 per page, infinite scroll for more)
  - Pull-to-refresh
  - Icons by notification type (wallet = green, delivery = blue, general = grey)
  - Unread notifications highlighted with blue background
  - Relative timestamps ("5m ago", "2h ago", "Jun 30")
  - Empty state when no notifications
- Bell icon with unread badge added to home page header:
  - Red badge with count (shows "9+" for 10+)
  - Tapping opens notifications page
  - Badge resets to 0 after viewing (mark-all-as-read on screen open)
  - Count refreshed on returning from notifications page and on home page init
