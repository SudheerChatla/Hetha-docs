## 1. Wallet tab follows the live balance

Commit `Hetha_app` **`5d67e1b`**. Worked on 2026-10-06; full analysis in
[CHANGES_2026-10-06.md](./CHANGES_2026-10-06.md).

### Problem
`lib/screens/wallet/walletpage.dart` loaded its data once, in `initState`. The
bottom tabs are kept alive in an `IndexedStack` (`main_wrapper.dart`), so that
ran **once per app session**. After that the tab showed a stale balance and
transaction list after:
- a wallet payment at checkout;
- the daily subscription deduction;
- refunds (cancellation, short delivery);
- an admin credit or debit;
- a top-up made from another screen.

The refresh icon reloaded transactions only, not the balance. There was no
pull-to-refresh and no reload on return from the background.

*Example:* the Wallet tab showed ₹1,000. The customer paid ₹300 at checkout
and Home showed ₹700, but the Wallet tab still showed ₹1,000 until the app was
restarted.

### Fix
| Change | Detail |
|---|---|
| Live balance | The page is now a `ConsumerStatefulWidget` following the existing `userDataProvider` stream: the Realtime `.stream()` on the customer's own `users` row, already used by Home, Checkout and Subscriptions. **No new Realtime connection or channel.** |
| Refetch on money movement | A `wallet_balance` change shows at once, then transactions + days-left re-fetch after a 400 ms debounce. Every wallet movement goes through `internal.apply_wallet_delta`, so a balance change means a new transaction row. Profile edits (same balance) are ignored. |
| No double load | The stream's first value only sets the balance; the initial load already fetched the rest. |
| One refresh at a time | `_refreshAll()` runs both queries together; a request during a refresh re-runs once afterwards instead of overlapping. |
| Resume | Refreshes after 20 s or more in the background (`ResumeRefreshPolicy`, same as the Orders screen). Realtime does not replay missed events. |
| Pull-to-refresh | On the transaction list, including the empty state; reloads the balance and days-left too. |
| Refresh icon | Reloads everything (was transactions only); tooltip "Refresh". |
| After a top-up | Uses `_refreshAll()`, which also covers a dropped Realtime connection. |
| Crash fix | `mounted` checks before every `setState` in both fetches (was a possible "setState() called after dispose()"). |
| Rule extracted | `lib/utils/wallet_stream_action.dart` (new): `ignore` / `showBalance` / `showBalanceAndRefetch`, kept out of the widget so it is unit-tested. |
| Tests | `test/wallet_stream_action_test.dart` (new, 6 tests): no balance yet, first value, same balance, debit, credit, drop to zero. |
| Comment | `lib/services/notification_service.dart`: corrected the claim that the wallet screen was already live. |

### ⏳ Device test
1. Open the Wallet tab.
2. Admin panel → Customers → this customer → Wallet → credit ₹10. Balance and
   transaction update within 1–2 s without leaving the tab.
3. Pay for an order from the wallet, then return to the Wallet tab. Balance
   and transaction both show.
4. Background the app for more than 20 s, make an admin credit meanwhile,
   reopen. The Wallet tab shows it.
5. Pull down on the transaction list. Everything reloads.

Known limits (⚠️ follow-up):
- "Days left" ignores paused days and one-time day edits, and does not update
  when a subscription changes without a balance change.
- Pull-to-refresh works on the list area only, not the balance banner.

## 2. Android release build fixed for Flutter 3.47.6

Commit `Hetha_app` **`85adc05`**.

### Problem
`flutter build apk --split-per-abi` failed after the local Flutter SDK was
upgraded to **3.47.6**, which refuses to build below minimum versions of the
Android tools. Each failure appeared only after the previous one was fixed.

### Version changes
| Component | Was | Flutter minimum | Now | File |
|---|---|---|---|---|
| Gradle (wrapper) | 8.11.1 | 8.14.0 | **8.14.3** | `android/gradle/wrapper/gradle-wrapper.properties` |
| Android Gradle Plugin (AGP) | 8.9.1 | 8.11.1 | **8.11.1** | `android/settings.gradle` |
| Kotlin Gradle Plugin | 2.1.0 | 2.2.20 | **2.2.20** | `android/settings.gradle` |

Each was raised to the smallest version that passes (Gradle: the last 8.x
patch), to keep the jump small. Compatibility: AGP 8.11 needs Gradle ≥ 8.13;
Kotlin 2.2.20 works with AGP 8.11 and Gradle 8.14.

### Kotlin build-script change (`android/app/build.gradle`)
Kotlin 2.2 turned `android { kotlinOptions { jvmTarget = ... } }` into a build
error. Replaced with a top-level block (same Java 17 target, matching
`compileOptions`):

```groovy
kotlin {
    compilerOptions {
        jvmTarget = org.jetbrains.kotlin.gradle.dsl.JvmTarget.JVM_17
    }
}
```

### Files the Flutter tool rewrites (now kept and committed)
Flutter 3.47.6 re-applies these on every build. Earlier sessions reverted
them; they are now committed so the repo matches the SDK it is built with.

| File | Change |
|---|---|
| `pubspec.lock` | SDK-bundled packages re-pinned: `matcher` 0.12.19 → 0.12.20, `meta` 1.17.0 → 1.19.0, `test` 1.30.0 → 1.31.1, `test_api` 0.7.10 → 0.7.12, `test_core` 0.6.16 → 0.6.18, `vector_math` 2.2.0 → 2.4.3. **No app dependency changed.** |
| `android/gradle.properties` | `android.builtInKotlin=false`, `android.newDsl=false`: AGP 9 opt-outs added by Flutter's migrator; harmless on AGP 8.11 |
| `analysis_options.yaml` | `analyzer.exclude` for `build/` and the platform folders |

⚠️ Everyone building the app should use **Flutter 3.47.x**. Older SDKs re-pin
`pubspec.lock` the other way.

### Gradle download timed out on this network (machine-specific workaround)
**Symptom.** In both Claude's sandbox and the developer's terminal, the Gradle
wrapper failed with `java.net.ConnectException: Connection timed out` while
downloading Gradle 8.14.3.

**Cause, measured.** `services.gradle.org` redirects to
`release-assets.githubusercontent.com` (GitHub's file host):

| Host | TCP connect time |
|---|---|
| `services.gradle.org` | 0.3 s |
| `release-assets.githubusercontent.com` | **≈ 20 s, every time** (4 of 4) |
| `dl.google.com`, `repo.maven.apache.org`, `plugins.gradle.org` | < 0.5 s |

The first address the GitHub host returns is unreachable from this network;
after about 20 s Windows gives up and `curl` moves on to the next address,
which works. Java's downloader in the Gradle wrapper does not retry another
address, so it fails. Not IPv6: the host has no IPv6 address. The project's
`gradle-wrapper.jar` is also very old (2.10, from Flutter's template) with no
network-timeout setting.

**Workaround (this machine only; not in the repo).** Downloaded
`gradle-8.14.3-all.zip` with `curl` into
`%USERPROFILE%\.gradle\wrapper\dists\gradle-8.14.3-all\10utluxaxniiv4wxiphsi49nj\`.
SHA-256 verified against Gradle's published checksum
(`ed1a8d686605fd7c23bdf62c7fc7add1c5b23b2bbc3721e661934ef4a4911d7c`). The
wrapper then used the local zip.

⚠️ **Another machine on this network will hit the same timeout** the first
time it needs Gradle 8.14.3. Same fix: download the zip in a browser or with
`curl` and place it in that machine's `dists\gradle-8.14.3-all\<hash>\`
folder. The folder appears after the first failed attempt.

### Build result
| Output | Size | Use for |
|---|---|---|
| `app-arm64-v8a-release.apk` | 26.2 MB | almost all current phones |
| `app-armeabi-v7a-release.apk` | 24.3 MB | older 32-bit phones |
| `app-x86_64-release.apk` | 27.7 MB | emulators |

Location: `Hetha_app/build/app/outputs/flutter-apk/`. First run ≈ 17 min
(including downloads). These APKs were built **before** the banner change (§3)
was made; rebuild to include it.

Warnings only:
- ⚠️ Flutter will **soon** raise its minimums again: **Gradle ≥ 9.1.0**,
  **AGP ≥ 9.0.1**, **Kotlin ≥ 2.3.20**. AGP 9 changes the build-script DSL
  (the "Starting AGP 9+, only the new DSL interface will be read" notice), so
  this needs its own migration.
- `javac` "source/target value 8 is obsolete" and deprecation notes come from
  third-party plugins' Java code. Harmless.

## 3. Home banner carousel: whole image visible (`BoxFit.contain`)

Commit `Hetha_app` **`6889f45`**.

**Request.** The whole banner image should always be visible.

**Before.** The banner `CarouselSlider` in `lib/screens/home/home_page.dart`
showed each image with `fit: BoxFit.cover`. The slide is full width × 180 px,
so a banner whose shape didn't match was **cropped** at the edges (top/bottom
or the sides).

**Now.** `fit: BoxFit.contain`, with a comment explaining why. The whole image
is always visible, never cropped or stretched. When the banner's shape doesn't
match the slide, the container's beige background (`#ECE2D8`) shows in the
spare space. Rounded corners, shadow, autoplay (3 s) and tap-to-open links are
unchanged.

| Fit | Fills the slide | Crops | Distorts |
|---|---|---|---|
| `cover` (before) | yes | yes | no |
| **`contain` (now)** | no, beige bands possible | **no** | no |

**Banner artwork tip.** The slide is about **2:1 to 2.2:1** on phones.
Banners made at about **1080 × 540** fill it with little or no band. Keep text
away from the edges.
